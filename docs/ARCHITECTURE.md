# Architecture

`grad` is a standalone, self-hostable training and serving platform designed around one authoritative OpenAPI 3.1 contract (`spec/openapi.yaml`) and strict self-hosted / Cloud parity.

## Components

1. **Control Plane (`server/api/`)**: TypeScript + Hono (`@hono/zod-openapi`), PostgreSQL + S3 (or local filesystem). Zero Valkey, ClickHouse, or Temporal dependencies in self-hosted mode, and no in-process state that breaks with several API replicas.
   - **Routes** (`src/routes/`) are thin: user routes for datasets/imports/uploads, runs, checkpoints, artifacts, evals, keys and the usage ledger (`GET /v1/usage`), plus 501 stubs for the Cloud-served deployments/route/embeddings/feedback paths; `trainer-jobs.ts` is the worker protocol; `blobs.ts` serves HMAC-signed upload/download URLs when storage is the local filesystem. A global error handler renders every error (unknown route, malformed JSON, validation, thrown) as `application/problem+json` with a `request_id`. List endpoints share `?limit&cursor` → `{data, next_cursor}` keyset pagination.
   - **Services** (`src/services/`) own business rules and transactions: `jobs.ts` (the one queue: claim, heartbeat, lease expiry and the attempt rule for train, import and eval jobs), `runs.ts` (run lifecycle, budgets), `imports.ts`, `datasets.ts`, `uploads.ts` (content-addressed keys, no upload rows), `usage.ts` (incremental usage ledger and the Cloud exporter), `evals/` (in-server eval executor) and `maintenance.ts` (lease expiry, checkpoint expiry, staged-upload and job-event sweeps, usage export).
   - **Store** (`src/store/`): per-resource repository interfaces (`types.ts`) implemented on Postgres (`postgres/`) and verified by `test/store-contract.test.ts`. Ten tables (`migrations/0001_initial.sql`): `grad_api_keys`, `grad_datasets`, `grad_dataset_parts`, `grad_jobs`, `grad_job_events`, `grad_runs`, `grad_evals`, `grad_eval_outputs`, `grad_artifacts` (checkpoints and releases), `grad_usage`. Create endpoints store the caller's Idempotency-Key and a request hash on the row they create. Tests run on a real Postgres too: one schema per test file, emptied per test. `store.transaction()` gives atomic multi-repository writes; migrations are versioned (`grad_schema_migrations`) under an advisory lock.
   - **Storage** (`src/storage/`): `ObjectStore` (local + S3). Keys are content-addressed (`ws/<ws>/jobs/<job>/<attempt>/<sha256>`, `ws/<ws>/datasets/<dataset>/<sha256>.jsonl`, staged imports under `uploads/<ws>/<sha256>`); presigned PUTs bind Content-Length and `x-amz-checksum-sha256`, and the local-FS proxy verifies the bytes itself.
   - **Adapters** (`adapters.ts`, `adapters-cloud.ts`) for Auth and Billing (tested against `test/fixtures/fake-cloud-api.ts`). Deploy, routing, embeddings and feedback are served by Gradiated Cloud; grad-server keeps 501 stubs on their paths (`deploy_unavailable` / `inference_unavailable`).
   - **Trainer protocol v1** (`/v1/trainer-jobs/*`, platform scope `trainer:worker`, never implied by `admin`): `claim` (train | import jobs; pinned dataset version, resume checkpoint, remaining budget), background `heartbeat`, `progress`, `uploads` (presigned or signed PUT), `checkpoints`, `records` (import batches), `complete` (one transaction: artifact + run + usage row; cost = tokens × catalog price). Usage is billed in increments while an attempt runs (every `USAGE_FLUSH_TOKENS` or `USAGE_FLUSH_SECONDS`, at checkpoints, and at the end); on Cloud a heartbeat stops a run whose workspace ran out of balance (`insufficient_balance` → resumable `stopped_budget`). A claim retried by the same worker returns its own job; worker writes are stored once per `(job, attempt, seq|step)`. Expired leases and abandoned attempts requeue as `attempt + 1` until `MAX_ATTEMPTS` of them have happened. KEDA autoscales workers from a Postgres query (queued + running jobs).
   - **Evals** run asynchronously in the server against an OpenAI-compatible endpoint (`INFERENCE_BASE_URL`, judges on `JUDGE_BASE_URL`); regex rubrics run in a worker thread with a hard timeout; Python function scorers run in the SDK (`awaiting_scores`). Nothing is simulated: without inference the API returns `501 inference_unavailable`.
2. **Training Runtime & Connectors (`server/trainer/`)**: Python `grad-trainer`. `grad_trainer/worker.py` is the protocol-v1 client (heartbeat thread, streaming bundle uploads, graceful SIGTERM, backoff, clear exit on a rejected key) and calls recipes through the seam types in `grad_trainer/runner_types.py`. Recipes implement all 6 v0 recipes (`sft`, `dpo`, `router`, `decision`, `cartridge`, `embedding`), `gradiated.cartridge/1` safetensors export, deterministic SHA-256 `.grad.tar.gz` bundles, and 7 Tier-1 trace connectors (`grad_trajectories`, `gradiated`, `otel`, `langfuse`, `posthog`, `braintrust`, `langsmith`).
3. **OpenAPI 3.1 Codegen (`scripts/generate-sdks.mjs`)**: Deterministic generator emitting zero-drift wire clients for TypeScript, Python, Go, and Rust (`--check` enforced in CI).
4. **4 Idiomatic SDKs (`sdks/{python,typescript,go,rust}`)**: Thin façades over the generated clients with fail-closed SHA-256 artifact verification.
5. **Rust CLI (`cli/`)**: Single binary `grad` built on `grad-sdk`.
6. **Packaging (`server/docker-compose.yml`, `server/helm/grad/`)**: Local Docker Compose stack (`grad local up`) and production Kubernetes Helm chart with optional KEDA scale-to-zero and air-gapped model/judge overrides.

## Locked v0 Scope
- **8 v0 Recipes:** `sft`, `dpo`, `router`, `decision`, `cartridge`, `embedding`, `distill`, `reward` (a forward-compatible typed contract is retained for Wave 2 `grpo`).
- **Parameter-Efficient LLMs Only:** `LoRA`, `PrefixKV`, `FrozenHead` (no `adapters.Full()` for LLMs; `EmbeddingRecipe` trains the 33M `baai/bge-small-en-v1.5` encoder internally).
- **Single-Command Deploy (Gradiated Cloud):** `deploy()` / `grad deploy` and rollback hit the Cloud product API on the same paths; self-hosted servers answer `501 deploy_unavailable` with the download-and-serve hint.
- **Environments are post-v0:** `grad env serve` (outbound environment workers) and environment evals return in Wave 2, rebuilt on the Postgres job queue.
